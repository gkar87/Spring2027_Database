How to use this page

  • Each grey box is an editor. Press Run, or Ctrl+Enter (Cmd+Enter on a Mac). A box may hold several statements; each result is shown.
  • Examples that change data start with BEGIN; and end with ROLLBACK;, so the change is undone afterwards. A box runs as one unit: if any statement in it fails, none of its changes are kept.
  • Reset database, at the top, puts the starting data back, whatever you changed.
  • Exercises have a Check answer button. It runs your statements inside a transaction and rolls them back, so checking never changes the data. Your solved exercises are remembered in this browser only.
  • This page runs SQL, not Python. Where Lab 6's Python writes %s, write the value here, as in the examples.

1. Parameters, and what happens without them

Slides 9 to 11. A program that pastes a user's text into its SQL lets the user write part of the query. One apostrophe is enough to change what the database runs.

A driver like psycopg sends the SQL and the values separately, and the database fills the values in after it has parsed the query, so a value can never become SQL. PREPARE and EXECUTE do the same by hand: the query is parsed once, with $1 as a hole, and each EXECUTE only supplies a value.

Parameters hold values only, never table or column names. When a name has to be chosen at run time, quote it as a name: in SQL, format() with %I for a name and %L for a value; in psycopg, the psycopg.sql module (slide 11).

2. Check, then act, in one transaction

Slides 14 to 17. Lab 6's enroll asks three questions before it inserts. psycopg starts a transaction with the first statement, so all of them see the same database. Here is the same conversation in SQL, for student 54321 and CS-347: one prerequisite is missing, so the program inserts nothing.

A constraint is the last line of defense. Enrolling the same student twice breaks the primary key of takes, and the statement is refused. In a program, that refusal arrives as psycopg.errors.UniqueViolation, and the transaction is then aborted until the program rolls back.

RETURNING sends back the rows a change touched, so a program needs no second query to learn what happened. Joining the table to itself in an UPDATE lets RETURNING show the value before the change as well as after it.

ON CONFLICT DO NOTHING turns "insert unless it is already there" into one statement. RETURNING then shows one row when the insert happened and none when it did not.

3. Fewer, smaller round trips

Slides 19 to 21. Every statement a program sends waits for the network both ways. A loop that sends one query per department (the "N+1" pattern) pays that wait 1 + N times:

The same answer in one round trip. The LEFT JOIN keeps Economics, which has no students.

A screen shows a page at a time. OFFSET is the easy way, but the database still reads every row it skips, and a row inserted meanwhile shifts every later page by one.

Keyset pagination remembers the last key shown and starts after it. With an index on the key, which a primary key has, the database jumps straight there, however deep the page.

Exercises

Write the SQL a program would send, with the values written in. Check each answer; checking never changes the data.

The roster of CS-315 in Spring 2026: each student's id, name and grade, ordered by name.

Hint

Join takes to student on the id, and put the course, semester and year in the WHERE.

Show a solution
SELECT s.id, s.name, t.grade
FROM takes t
JOIN student s ON s.id = t.id
WHERE t.course_id = 'CS-315'
  AND t.semester = 'Spring' AND t.year = 2026
ORDER BY s.name;

A search box received AR. Show the id and name of every student whose name contains it, in any case, ordered by name.

Hint

ILIKE ignores case. The value a program would send as the parameter is '%AR%'.

Show a solution
SELECT id, name
FROM student
WHERE name ILIKE '%AR%'
ORDER BY name;

Student 12345 wants to take CS-319. Show the prereq_id of each prerequisite of CS-319 that 12345 has not passed, with a grade that is not NULL and not F.

Hint

Example 2.1's last query, with the other student and course.

Show a solution
SELECT p.prereq_id
FROM prereq p
WHERE p.course_id = 'CS-319'
  AND NOT EXISTS (
    SELECT 1 FROM takes t
    WHERE t.id = '12345' AND t.course_id = p.prereq_id
      AND t.grade IS NOT NULL AND t.grade <> 'F');

Enroll student 54321 in CS-315 for Fall 2027, with no grade yet, in one statement that also sends back the new row's id, course_id, semester and year.

Hint

An INSERT with RETURNING, as in example 2.4. The grade is NULL.

Show a solution
INSERT INTO takes VALUES ('54321', 'CS-315', 'Fall', 2027, NULL)
RETURNING id, course_id, semester, year;

A screen lists students four at a time, by id. Page 1 ended with id 23121. Show page 2's id and name with keyset pagination, not OFFSET.

Hint

Example 3.4, with the last id of page 1 and a page of four.

Show a solution
SELECT id, name
FROM student
WHERE id > '23121'
ORDER BY id
LIMIT 4;

Replace this loop with one query. A program reads every course, then for each one sends SELECT count(*) FROM takes WHERE course_id = …. Show each course_id with its number of enrollments, 0 included.

Hint

Example 3.2's shape: start from course, LEFT JOIN takes, and count a column of takes.

Show a solution
SELECT c.course_id, count(t.id) AS enrollments
FROM course c
LEFT JOIN takes t ON t.course_id = c.course_id
GROUP BY c.course_id;

Preview a 3% raise for Physics in one UPDATE: send back each instructor's name, salary before and salary after, rounded to cents.

Hint

Example 2.3, with another department and percentage. The checker rolls back for you.

Show a solution
UPDATE instructor i
SET salary = round(o.salary * 1.03, 2)
FROM instructor o
WHERE o.id = i.id AND i.dept_name = 'Physics'
RETURNING i.name, o.salary AS old_salary, i.salary AS new_salary;

The program's "who could sign up" button for CS-315: show the id and name of every student who has passed every prerequisite of CS-315 and has never taken CS-315.

Hint

"Passed every prerequisite" is "there is no prerequisite they have not passed": a NOT EXISTS around exercise 3's query, with s.id in place of a fixed id. Add a second NOT EXISTS for "never taken".

Show a solution
SELECT s.id, s.name
FROM student s
WHERE NOT EXISTS (
        SELECT 1 FROM prereq p
        WHERE p.course_id = 'CS-315'
          AND NOT EXISTS (
            SELECT 1 FROM takes t
            WHERE t.id = s.id AND t.course_id = p.prereq_id
              AND t.grade IS NOT NULL AND t.grade <> 'F'))
  AND NOT EXISTS (
        SELECT 1 FROM takes t
        WHERE t.id = s.id AND t.course_id = 'CS-315');
