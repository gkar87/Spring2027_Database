Set up Python and psycopg

You need Python 3.10 or newer and psycopg 3, the PostgreSQL driver for Python. Check Python with python --version (py --version on Windows). Then install psycopg once, in the lab folder:

  • Windows, in PowerShell: 
    py -m pip install "psycopg[binary]"
  • macOS and Linux: make a virtual environment, so the install does not touch the system's Python, then install into it. Run the source line again in each new Terminal window before you run the lab. 
    python3 -m venv .venv
source .venv/bin/activate
python -m pip install "psycopg[binary]"
  • Colab, after the Lab 0 setup cell: 
    !pip install "psycopg[binary]"

Check it with python -c "import psycopg; print(psycopg.__version__)". The program connects with dbname=university, as psql does. If your database asks for a password (on Windows it does), tell the program in the terminal before you run it, never in lab6.py. These lines last until you close the PowerShell window:

$env:PGUSER = "postgres"
$env:PGPASSWORD = "the password you chose in Lab 0"

Part B: three questions in SQL, seven functions in Python

In lab6.sql

  1. Q1. Create the table enroll_log, where the program records every enrollment request it handles, accepted or refused:

    • log_id: an integer that PostgreSQL numbers by itself, GENERATED ALWAYS AS IDENTITY, the primary key.
    • student_id, course_id, semester, year: the request, with the same types and CHECKs as in takes, all NOT NULL.
    • outcome: varchar(8), NOT NULL, either enrolled or refused.
    • reason: varchar(100). A CHECK that spans two columns makes it required when the outcome is refused.
    • logged_at: a timestamptz, NOT NULL, with DEFAULT now().

    Give it no foreign keys: the log must be able to record a refused request for a student id that does not exist.

  2. Q2. Find the enrollments already in takes that break a prerequisite: each id, the student's name, the course_id and the prerequisite missing, ordered by id, course_id and missing. A prerequisite is passed when the student has a takes row for it with a grade that is not NULL and not 'F'. Use NOT EXISTS. You should get eight rows.

  3. Q3. Create a role registrar_app for the program, with only the privileges it needs: SELECT on student, course, prereq, takes and department, and INSERT on takes and enroll_log. Then SET ROLE registrar_app;, count the rows of takes as enrollments, run the DELETE that is in the starter file, which must be refused, and RESET ROLE;.

In lab6.py

Each function receives an open connection, conn. Its docstring says exactly what to return. Use conn.execute(sql, params) with a %s for each value and a tuple of values, as the given function log() does, and never build SQL with +, f-strings, format() or %. A function you have not written yet prints "not written yet", so you can run the program at any time.

  1. P1. roster(conn, course_id, semester, year): who took one offering of a course, with their grades.

  2. P2. find_students(conn, text): students whose name contains text, in any case. main() also calls it with ' OR 1=1 --, which must return no rows.

  3. P3. missing_prereqs(conn, student_id, course_id): Q2's idea for one student and one course.

  4. P4. enroll(conn, student_id, course_id, semester, year): check, then insert into takes with a NULL grade, or refuse, and log every request. The docstring gives the four reasons and their order. When the INSERT raises psycopg.errors.UniqueViolation, the transaction is aborted: call conn.rollback() before you log, or the log INSERT fails too. Commit once, at the end.

  5. P5. preview_raise(conn, dept_name, percent): run the UPDATE with RETURNING to see each old and new salary, then roll back, so the raise is shown but never kept. main() reads the salaries afterwards to prove nothing changed.

  6. P6. students_page(conn, after_id, size): one page of a list, for a screen that shows size students at a time. Keyset pagination, as on slide 21: WHERE id > %s ORDER BY id LIMIT %s.

  7. P7. dept_counts(conn): every department and its number of students, 0 included, in one query.

§

If something goes wrong

  • "No module named 'psycopg'": psycopg is installed for a different Python. On macOS and Linux, run the source .venv/bin/activate line first; on Windows, install and run with the same py.
  • "error: externally-managed-environment" from pip: your system protects its own Python. Use the virtual environment in Set up.
  • "connection failed" or "password authentication failed": the server is not running, or the program does not know your user and password. Set PGUSER and PGPASSWORD as in Set up, in the same window.
  • "current transaction is aborted, commands ignored until end of transaction block": an earlier statement failed and nothing rolled back. In enroll, call conn.rollback() in the except before you log.
  • An error that the query has a different number of placeholders than parameters: the tuple has the wrong number of values. A tuple of one value needs a comma: (text,).
  • P2 finds no one for 'ri': the % wildcards must be part of the value, "%" + text + "%", not of the SQL text.
  • "role "registrar_app" cannot be dropped because some objects depend on it": you granted it privileges in another database. Run DROP OWNED BY registrar_app; in that database, then run lab6.sql again.
