1. A relation is a table of tuples

Slides 15 and 16. A relation has a fixed set of attributes (the columns) and a set of tuples (the rows). Run the query to see every tuple of department.

The schema of a relation is its name and attributes. PostgreSQL keeps the schema in tables of its own, so you can query it like any other data.

The instance is the set of tuples right now. The degree is the number of attributes; the cardinality is the number of tuples.

2. Asking for some columns and some rows

Slides 23 and 24. A query says what you want: which columns (SELECT), from which relation (FROM), and which rows qualify (WHERE). Next week these become the relational algebra operators projection and selection.

Press Watch it run to see the three clauses happen in order. Edit the query first if you like: any single-table SELECT … FROM … WHERE … works.

Try changing 'Comp. Sci.' to 'comp. sci.'. String comparison is exact, so the answer is empty, not an error.

3. Sets in theory, bags in SQL

Slide 17. A relation is a set, so it never holds the same tuple twice. A SQL query result is a bag (a multiset): duplicates stay unless you ask for DISTINCT. Compare the row counts of these two.

Order is not part of a relation either. Without ORDER BY, PostgreSQL may return rows in any order; with it, the order is guaranteed.

4. Keys: no two tuples agree

Slide 18. id is the primary key of student, so PostgreSQL refuses a second student with id 00128. Run it: the error is the point.

Change the id to '00999' and run it again: now it succeeds. Then run Example 3.1 again to see the new tuple. Reset database removes it.

A key for takes needs four attributes. One student can take one course more than once, in different terms, as Drew Kim (id 45678) did with CS-101.

5. Foreign keys: references must point somewhere

Slides 19 to 21. student.dept_name references department. There is no Astrology department, so this insert fails.

The rule works in the other direction too. Deleting the Music department would leave a student, an instructor and a course pointing at nothing.

A CHECK constraint is a third kind of rule. The schema says a salary must be above 29,000.

6. NULL means "no value"

Slide 22. Three enrollments in Spring 2027 have no grade yet. A comparison with NULL is neither true nor false but unknown, and WHERE keeps only rows where the condition is true. So the first query finds nothing.

Press Watch it run on both: the first marks every row unknown, the second marks three rows true.

Exercises

Write each query, then press Check answer (or Ctrl+Shift+Enter). Column names don't matter, but the columns must come in the order asked, and row order doesn't matter unless the exercise says so. Exercises 1 to 5 are for everyone; exercise 6 is a stretch.

List the names of all instructors in the Comp. Sci. department.

Hint

Example 2.1 is almost the answer. Keep only the column asked for.

Show a solution
SELECT name
FROM instructor
WHERE dept_name = 'Comp. Sci.';

List the titles of all courses worth 4 credits.

Hint

Numbers are compared without quotes: credits = 4.

Show a solution
SELECT title
FROM course
WHERE credits = 4;

List each building that houses a department, once.

Hint

Two departments share a building. Section 3 shows how to remove duplicates.

Show a solution
SELECT DISTINCT building
FROM department;

List the name and total credits of every student with more than 100 credits.

Hint

"More than 100" is > 100, so a student with exactly 100 would not count.

Show a solution
SELECT name, tot_cred
FROM student
WHERE tot_cred > 100;

Which enrollments have no grade yet? List the student id and course_id.

Hint

Section 6: = NULL never matches.

Show a solution
SELECT id, course_id
FROM takes
WHERE grade IS NULL;

List the name and salary of every instructor in Physics or Comp. Sci. who earns more than 90,000, highest salary first. Row order counts here.

Hint

Mixing AND and OR needs parentheses: (a OR b) AND c. Or use dept_name IN ('Physics', 'Comp. Sci.').

Show a solution
SELECT name, salary
FROM instructor
WHERE dept_name IN ('Physics', 'Comp. Sci.')
  AND salary > 90000
ORDER BY salary DESC;
