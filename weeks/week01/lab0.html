Part A: warm up in the playground (10 minutes)

Open the week 1 playground. It runs PostgreSQL inside your browser, so it works before you install anything.

Part B: install PostgreSQL (pick one path)

PostgreSQL 14 or newer works for this course; 18 is the current release. Path 1 is recommended because you keep the same database all term. Path 2 needs no install, but a Colab session forgets everything when it closes, so you rerun its setup cell each time.

You work on your own computer all term; there is no university lab for this course. Colab is fine until week 12, but by week 13 you need Path 1: Lab 8 and the project's milestone 4 run two sessions on the same server at once, which a Colab notebook can't. If your only computer can't install software, such as a Chromebook or a tablet, tell me in the first two weeks.

Path 1a: Windows

  1. Go to postgresql.org/download, choose Windows, and download the installer for the newest version.
  2. Run it and keep the default components: PostgreSQL Server, pgAdmin 4 and Command Line Tools. You can skip Stack Builder at the end.
  3. When asked, choose a password for the postgres user and write it down. Keep port 5432.
  4. Open PowerShell in your lab folder (in File Explorer, type powershell in the address bar and press Enter). Tell PowerShell where psql is, changing 18 if you installed another version: 
    $pg = "C:\Program Files\PostgreSQL\18\bin"
& "$pg\psql.exe" -U postgres -c "SELECT version();"
    Type your password when asked. If you see a version line, Path 1a is done. In Parts C and D, write & "$pg\psql.exe" -U postgres wherever the commands say psql, and & "$pg\createdb.exe" -U postgres for createdb.

Path 1b: macOS

  1. Download Postgres.app, move it to Applications, open it, and click Initialize.
  2. In Terminal, add its command-line tools to your path (this is the command Postgres.app's own page gives), then open a new Terminal window: 
    sudo mkdir -p /etc/paths.d &&
echo /Applications/Postgres.app/Contents/Versions/latest/bin | sudo tee /etc/paths.d/postgresapp
  3. Check it: psql -c "SELECT version();". Postgres.app logs you in as your Mac user with no password.

Path 1c: Linux (Ubuntu or Debian)

sudo apt update
sudo apt install postgresql
sudo -u postgres createuser --superuser "$USER"
psql -d postgres -c "SELECT version();"

Path 2: Google Colab, no install

  1. Open Google Colab and create a new notebook.
  2. Upload the three lab files with the folder icon on the left, then Upload.
  3. Run this setup cell. It takes about a minute, and you rerun it whenever the session restarts: 
    !apt-get -qq update > /dev/null && apt-get -qq install -y postgresql > /dev/null
!service postgresql start
!sudo -u postgres psql -q -c "CREATE ROLE root SUPERUSER LOGIN;"
!psql -d postgres -c "SELECT version();"
  4. In Parts C and D, start each command with !, for example !psql -d university -f lab0_check.sql.

After a Colab restart, rerun the setup cell and Part C's two commands. The CREATE ROLE line then reports that the role exists; that is fine.

Part C: load and check the database

Create an empty database named university, load the sample data into it, and run the check:

createdb university
psql -d university -f university.sql
psql -d university -f lab0_check.sql

Loading prints five NOTICE: table "…" does not exist, skipping lines the first time. They are expected: the script removes old copies of the tables before creating new ones. The check should print:

Expected output of lab0_check.sql
relationexpectedfoundstatus
department66PASS
instructor1010PASS
student1212PASS
course99PASS
takes2222PASS

If a line says FAIL, run the load command again; university.sql always starts from scratch.

Optional: open pgAdmin (installed with Path 1a, or from pgadmin.org) and find the five tables under Databases → university → Schemas → public → Tables. Everything in this course can also be done in psql alone.

Part D: your first queries

Open lab0.sql in any text editor (VS Code, Notepad, TextEdit in plain-text mode). Q1 and Q2 are written for you. Write Q3 to Q6 under their comments:

  1. Q3. The name and budget of every department in the Hale building.

  2. Q4. The name and total credits of every Physics student, most credits first.

  3. Q5. Add a made-up student (not yourself) with an id that is not taken, any department that exists, and 0 credits. Then select that one row.

  4. Q6. Write one INSERT or UPDATE that breaks a constraint on purpose: a primary key, a foreign key or a CHECK. Say which in a comment. An error here is the right answer.

Then run the whole file and save everything it prints:

psql -d university -e -f lab0.sql > lab0_output.txt 2>&1

-e prints each query above its result, and 2>&1 keeps the error messages in the file too. Open lab0_output.txt and check that Q6's error is in it.

Running the file twice makes Q5 fail the second time, because your student already exists. That is a primary-key violation, and it shows exactly what keys are for. To start clean, reload university.sql and run the file again.

Part E: two short answers

Write these in lab0_answers.txt, under their headings, three or four sentences each. Fill in your name, student ID, course and section at the top, and the AI use line at the end. Save it as plain text: in TextEdit choose Format › Make Plain Text first; Notepad and VS Code save plain text already.

  1. E1. Which constraint did your Q6 break? If the database had accepted that row, what would go wrong later, and for whom?

  2. E2. The primary key of takes is (id, course_id, semester, year). Using a row from the data, explain why (id, course_id) alone would not be enough.

If something goes wrong

  • "psql is not recognized" or "command not found": the tools are not on your path. On Windows, use the $pg line from Path 1a; on a Mac, open a new Terminal after step 2 of Path 1b.
  • "password authentication failed": on Windows, use the password you chose during install, with -U postgres.
  • "database "university" does not exist": run createdb university first.
  • "database "university" already exists": fine. Skip createdb and just reload university.sql.
  • Anything else: copy the exact error message and bring it to office hours, Tuesday and Wednesday 12:00–3:00 p.m., MIC room D159, or post it in the week 1 discussion in Brightspace. The PostgreSQL tutorial, chapter 1, covers installation questions.
