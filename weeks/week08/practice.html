About the midterm

  • The exam uses the university database, with the eight tables in the schema at the top of the review playground. A copy of the schema is printed on the exam, so you don't need it in your notes.
  • Write SQL the way you would type it. Small slips, like a missing semicolon, cost nothing; a wrong join or a missing GROUP BY column does.
  • Where a question asks why, one or two sentences is enough. Show the steps of a closure or a decomposition: most of the points are for the steps.
  • Online section: the same exam in Brightspace, with the same time limit, in the window announced there.

The answers below are one correct way. For SQL, any query that returns the same rows on every possible database, not just this one, earns full credit.

Part 1: relational algebra (15 points)

Write each query in relational algebra, using σ, π, ×, ⋈, ∪, − and ρ as on the week 2 slides.

  1. 1a (3 points). The names of instructors in the Physics department.

    Answer

    πname(σdept_name = 'Physics'(instructor)). On today's data: Sam Okafor and Kofi Mensah.

  2. 1b (4 points). The names of students who have taken CS-347.

    Answer

    πname(student ⋈ σcourse_id = 'CS-347'(takes)). Select before joining: it gives the same result with a smaller join. Four students.

  3. 1c (4 points). The ids of students who have never taken a course.

    Answer

    πid(student) − πid(takes). Both sides must have the same attributes before the difference, which is why both are projected to id first. One student: 61234, Emery Walsh.

  4. 1d (4 points). The highest salary of any instructor, without aggregation: use a product and a difference, as on the week 2 slides.

    Answer

    πsalary(instructor) − πi.salary(σi.salary < j.salary(ρi(instructor) × ρj(instructor))). The right side holds every salary that some other salary beats; what is left is the maximum, 98000. Noor Haddad's NULL salary is never beaten, because a comparison with NULL is never true, so on this data the result also holds NULL. Adding σsalary is not null on the left removes it.

Part 2: SQL queries (35 points)

  1. 2a (5 points). For each course that has been taken at least once, show its course_id and the number of different students who took it.

    Answer
    SELECT course_id, count(DISTINCT id) AS students
FROM takes
GROUP BY course_id;

    DISTINCT matters: Drew Kim took CS-101 twice. CS-101 has 5 different students.

  2. 2b (6 points). Show the name and tot_cred of every student whose tot_cred is above the average of all students.

    Answer
    SELECT name, tot_cred
FROM student
WHERE tot_cred > (SELECT avg(tot_cred) FROM student);

    An aggregate cannot go in WHERE directly; the subquery computes it once. The average is 62, and five students are above it.

  3. 2c (8 points). Show every instructor's name and the number of students they advise, including instructors who advise nobody, most advisees first.

    Answer
    SELECT i.name, count(a.s_id) AS advisees
FROM instructor i
LEFT JOIN advisor a ON a.i_id = i.id
GROUP BY i.id, i.name
ORDER BY advisees DESC;

    Two points each: the LEFT JOIN, counting a.s_id rather than * (which would give 1 to instructors with no advisees), grouping by the key, and the order. Four instructors show 0.

  4. 2d (8 points). Show the name, dept_name and salary of the highest-paid instructor in each department. If two tie, show both.

    Answer
    SELECT name, dept_name, salary
FROM (SELECT name, dept_name, salary,
             rank() OVER (PARTITION BY dept_name
                          ORDER BY salary DESC NULLS LAST) AS r
      FROM instructor) ranked
WHERE r = 1;

    A window function cannot go in WHERE, so it goes in a subquery. rank, not row_number, keeps ties. A correlated subquery with salary = (SELECT max(salary) …) also earns full credit.

  5. 2e (4 points). What does this return on the university database, and why is it not 11, the number of instructors?

    SELECT count(*) FROM instructor
WHERE salary > 80000 OR salary <= 80000;
    Answer

    10. Noor Haddad's salary is NULL, so both comparisons are unknown, and unknown OR unknown is unknown. WHERE keeps only rows where the condition is true.

  6. 2f (4 points). This query fails. Say why, and fix it so it shows each department's average salary.

    SELECT dept_name, name, avg(salary)
FROM instructor
GROUP BY dept_name;
    Answer

    name is neither grouped nor aggregated: a department has several names, and the group has one row. Remove name from the SELECT list (or group by it too, which gives one row per instructor and is not what was asked).

Part 3: changing data and constraints (10 points)

  1. 3a (4 points). What happens when you run DELETE FROM department WHERE dept_name = 'Music'; on the university database, and why? What would change if instructor.dept_name were declared ON DELETE SET NULL?

    Answer

    It is refused: instructor, student and course rows refer to Music, and those foreign keys use the default action, NO ACTION. With SET NULL on instructor, Diego Torres would stay with a NULL department, but the delete would still be refused by student and course unless they changed too.

  2. 3b (3 points). Write one statement that gives every instructor in Comp. Sci. a 3% raise.

    Answer
    UPDATE instructor
SET salary = salary * 1.03
WHERE dept_name = 'Comp. Sci.';

  3. 3c (3 points). After these statements, how many rows does department have, and why?

    BEGIN;
DELETE FROM department WHERE dept_name = 'Economics';
ROLLBACK;
    Answer

    Still 7. ROLLBACK undoes everything since BEGIN. (Without the ROLLBACK, the delete would succeed, since nothing refers to Economics, leaving 6.)

Part 4: E-R design (20 points)

A small clinic wants a database. Patients have an id, a name and any number of phone numbers. Doctors have an id, a name and one specialty. A patient books appointments; each appointment is with one doctor, at a date and time, and has a reason. At an appointment the doctor may write prescriptions, numbered 1, 2, 3 within that appointment, each for a drug and a dose. The clinic keeps a list of drugs, each with a code and a name.

  1. 4a (12 points). Draw an E-R diagram, in the textbook's notation, with keys underlined and cardinality and participation on every relationship.

    Answer
    • Entity sets: patient (patient_id, name, {phone}), doctor (doctor_id, name, specialty), drug (code, name), and appointment (appt_id, date_time, reason).
    • books: appointment to patient, many-to-one (arrow to patient), total on appointment (double line): every appointment has a patient.
    • with: appointment to doctor, many-to-one, total on appointment.
    • prescription: a weak entity set (double rectangle) with discriminator rx_no (dashed underline) and attribute dose, identified by appointment through a double diamond, total on prescription.
    • for: prescription to drug, many-to-one, total on prescription.

    Also full credit: appointment as a relationship among patient and doctor with date_time in its key, if the answer explains how prescriptions then attach (aggregation). Marks: 3 for entity sets and keys, 3 for the multivalued phone, 3 for the weak entity, 3 for cardinality and participation.

  2. 4b (8 points). Map your diagram to tables. Give each table's columns, primary key and foreign keys.

    Answer
    • patient(patient_id, name)
    • patient_phone(patient_id, phone), patient_id references patient
    • doctor(doctor_id, name, specialty)
    • drug(code, name)
    • appointment(appt_id, patient_id NOT NULL, doctor_id NOT NULL, date_time, reason), with foreign keys to patient and doctor. The two many-to-one relationships become columns, and total participation becomes NOT NULL.
    • prescription(appt_id, rx_no, code NOT NULL, dose), appt_id references appointment ON DELETE CASCADE, code references drug.

Part 5: dependencies and normal forms (20 points)

R(A, B, C, D, E) has the dependencies F = { A → B, B → C, C D → E }.

  1. 5a (4 points). Compute {A, D}+, showing each step. Is {A, D} a superkey?

    Answer

    Start {A, D}. A → B adds B. B → C adds C. C D → E adds E. {A, D}+ = {A, B, C, D, E}: every attribute, so yes.

  2. 5b (4 points). Give every candidate key of R, and say how you know there are no others.

    Answer

    {A, D} is the only one. A and D appear on no right side, so every key must contain both; {A, D} is already a superkey, so any other superkey contains it and is not minimal. A+ = {A, B, C} and D+ = {D}, so neither alone is a key.

  3. 5c (4 points). Is R in BCNF? Is it in 3NF? Name a dependency that decides each.

    Answer

    Neither. A → B breaks BCNF, because A is not a superkey. It also breaks 3NF, because B is not part of any candidate key.

  4. 5d (8 points). Decompose R into BCNF, showing each split. Is every dependency preserved?

    Answer

    Split on B → C: (B, C) and (A, B, D, E). In (A, B, D, E), A → B still breaks BCNF: split into (A, B) and (A, D, E). Result: (B, C), (A, B), (A, D, E), with keys B, A and (A, D).

    C D → E is lost: C and D are never in the same table, so it can only be checked with a join. A 3NF synthesis would keep it: (A, B), (B, C), (C, D, E), plus (A, D) for the key. Splitting first on A → B also earns full credit if each step is right.

CS 5200: the extra question

On the midterm, CS 5200 students answer one more question, worth 10 points; CS 4600 students do not see it. Their score is out of 110 and scaled to 100.

  1. G1 (10 points). Using only Armstrong's three axioms, prove the union rule: if α → β and α → γ, then α → βγ. Name the axiom used at each step.

    Answer
    1. α → γ, augmented with α, gives α → αγ (augmentation; αα = α).
    2. α → β, augmented with γ, gives αγ → βγ (augmentation).
    3. α → αγ and αγ → βγ give α → βγ (transitivity).
