Aggregates and groups

Functions that turn many values into one, GROUP BY to apply them per group, and HAVING to filter the groups.

Five functions turn a column into one value

SELECT count(*)      AS n_rows,
       count(salary) AS n_salaries,
       sum(salary)   AS total,
       avg(salary)   AS average,
       min(salary)   AS lowest,
       max(salary)   AS highest
FROM instructor;
Result: 1 row
n_rowsn_salariestotalaveragelowesthighest
1110809000809006100098000
  • count(*) counts rows, whatever they hold.
  • count(column) counts the values that are not NULL. 11 instructors, 10 known salaries.
  • sum, avg, min, max skip NULLs too. The average is 809,000 ÷ 10, not ÷ 11.
  • count(DISTINCT dept_name) counts different values: 6 departments have instructors.
Aggregate

A function that takes a whole set of values and returns one value. In the algebra it is written 𝒢, the grouping operator.

GROUP BY applies the aggregate once per group

The rule: every SELECT column is grouped or aggregated

-- error: column "instructor.name" must
-- appear in the GROUP BY clause or be
-- used in an aggregate function
SELECT dept_name, name, avg(salary)
FROM instructor
GROUP BY dept_name;

A group of three Comp. Sci. instructors has one average but three names. PostgreSQL will not pick one for you.

-- fix 1: aggregate the name too
SELECT dept_name, min(name), avg(salary)
FROM instructor GROUP BY dept_name;

-- fix 2: group by both (one row per person)
SELECT dept_name, name, avg(salary)
FROM instructor GROUP BY dept_name, name;

Grouping by a key

If you group by a table's primary key, PostgreSQL lets you select that table's other columns: GROUP BY s.id lets you show s.name.

See the error, playground example 1.4

WHERE filters rows; HAVING filters groups

SELECT dept_name, count(*) AS n
FROM instructor
WHERE salary > 80000        -- rows first
GROUP BY dept_name
HAVING count(*) >= 2        -- then groups
ORDER BY dept_name;
Result: 2 rows. Departments with at least two instructors earning over 80,000.

Queries inside queries

A subquery can stand for one value, a list, a yes-or-no test, or a whole table.

A subquery that returns one value

SELECT name, salary
FROM instructor
WHERE salary > (SELECT avg(salary)
                FROM instructor)
ORDER BY salary DESC;
Result: 5 rows, all above 80,900
namesalary
Avery Chen98000
Sam Okafor95000
Jordan Patel92000
Maria Lopez87000
Kofi Mensah87000

The inner query runs first and returns one number, 80,900. The outer query then uses it like a constant. You cannot write WHERE salary > avg(salary): WHERE sees one row at a time, and an average needs them all.

-- error: more than one row returned by
-- a subquery used as an expression
WHERE salary > (SELECT salary FROM instructor
                WHERE dept_name = 'Physics')

A subquery used as a value must return exactly one row and one column. If it returns none, its value is NULL.

Run both, playground example 2.1

Comparing with a list: IN, SOME and ALL

Set comparisons with subqueries, and their results on the course database

x > ALL (subquery)…and no value is NULLsalary > ALL (Mathematics salaries)nobody

Why nobody beats Mathematics

Mathematics salaries are 87,000 and NULL. For Avery Chen, 98,000 > 87,000 is true but 98,000 > NULL is unknown, and ALL needs every test true. It is the NOT IN trap from week 3 again.

Same meaning, other spellings

= SOME is IN. <> ALL is NOT IN. ANY is another name for SOME. > ALL without NULLs is > (SELECT max(…)).

Run all four, playground example 2.2

Correlated subqueries: the inner query sees the outer row

SELECT i.name, i.salary FROM instructor i
WHERE i.salary > (SELECT avg(j.salary) FROM instructor j WHERE j.dept_name = i.dept_name);

Run it, playground example 2.3

EXISTS asks only whether a row comes back

-- students enrolled in 2027: 3 rows
SELECT s.name FROM student s
WHERE EXISTS (SELECT 1 FROM takes t
              WHERE t.id = s.id
                AND t.year = 2027);
-- courses nobody has taken: CS-319
SELECT c.course_id FROM course c
WHERE NOT EXISTS (SELECT 1 FROM takes t
                  WHERE t.course_id = c.course_id);
  • EXISTS is true when the subquery returns at least one row. What the rows hold does not matter, so SELECT 1 is the usual spelling.
  • It is nearly always correlated: the inner WHERE mentions the outer row.
  • EXISTS is only ever true or false, never unknown. That makes NOT EXISTS the safe way to write "no matching row", where NOT IN can fail on a NULL.
Three ways to say "has none"

LEFT JOIN … IS NULL, NOT EXISTS, and EXCEPT. All three return CS-319 here. NOT IN would too, but only because takes.course_id cannot be NULL.

Run both, playground example 2.4

"Every" in SQL: division with NOT EXISTS

SELECT s.name FROM student s
WHERE NOT EXISTS (SELECT course_id FROM course WHERE dept_name = 'Comp. Sci.' AND credits = 4
                  EXCEPT
                  SELECT course_id FROM takes t WHERE t.id = s.id);

A subquery can also be a table, or a column

In FROM: a derived table

SELECT dept_name, round(avg_sal) AS avg_sal
FROM (SELECT dept_name, avg(salary) AS avg_sal
      FROM instructor
      GROUP BY dept_name) AS d
WHERE avg_sal > 85000;

The inner query's result is a table named d, so its alias avg_sal works in the outer WHERE. Same 3 rows as HAVING avg(salary) > 85000: Comp. Sci., Mathematics, Physics.

In SELECT: one value per row

SELECT d.dept_name,
       (SELECT count(*) FROM instructor i
        WHERE i.dept_name = d.dept_name) AS n
FROM department d
ORDER BY d.dept_name;

A correlated scalar subquery. Economics gets 0 here, because count of no rows is 0. It is the same answer as slide 9's count(i.id).

Run both, playground example 2.6

WITH and CASE

Name the steps of a long query, and turn values into categories.

WITH names a step, so a query reads top to bottom

WITH dept_avg AS (
  SELECT dept_name, avg(salary) AS a
  FROM instructor
  GROUP BY dept_name
)
SELECT i.name, i.salary, round(d.a) AS dept_avg
FROM instructor i
JOIN dept_avg d USING (dept_name)
WHERE i.salary > d.a
ORDER BY i.name;
  • A common table expression (CTE) is a named query that lives only for this statement.
  • Several can follow one WITH, separated by commas; each can use the ones before it.

CASE turns values into categories

SELECT CASE
         WHEN tot_cred >= 90 THEN 'Senior'
         WHEN tot_cred >= 60 THEN 'Junior'
         WHEN tot_cred >= 30 THEN 'Sophomore'
         ELSE 'Freshman'
       END AS standing,
       count(*) AS students
FROM student
GROUP BY standing
ORDER BY students DESC;
Result: 4 rows
standingstudents
Sophomore6
Senior4
Freshman2
Junior1
  • The first WHEN that is true wins, so the order of the tests matters.
  • With no ELSE, a row that matches nothing gets NULL.
  • PostgreSQL lets GROUP BY use the SELECT alias standing; the standard says to repeat the CASE.

Window functions

Aggregates that keep every row: rankings, comparisons with a group, and running totals.

A window function keeps the rows GROUP BY would collapse

SELECT name, salary,
       round(avg(salary) OVER (PARTITION BY dept_name)) AS dept_avg
FROM instructor ORDER BY dept_name, name;

Run it for all 11 instructors, playground example 4.1

Three ways to number rows, and what ties do

SELECT name, salary,
       rank()       OVER w AS rnk,
       dense_rank() OVER w AS dense,
       row_number() OVER w AS rownum
FROM instructor
WINDOW w AS (ORDER BY salary DESC NULLS LAST);
Rows 3 to 7 of 11

  • rank: ties share a number and leave a gap (4, 4, 6).
  • dense_rank: ties share, no gap (4, 4, 5).
  • row_number: always 1, 2, 3; ties are broken arbitrarily.
  • WINDOW w AS (…) names a window to reuse.

Run it, playground example 4.2

The top earner in each department

WITH ranked AS (
  SELECT name, dept_name, salary,
    rank() OVER (
      PARTITION BY dept_name
      ORDER BY salary DESC NULLS LAST
    ) AS rk
  FROM instructor
)
SELECT dept_name, name, salary
FROM ranked
WHERE rk = 1
ORDER BY dept_name;

Six rows, one per department: Hana Sato, Avery Chen, Tomas Novak, Maria Lopez, Diego Torres and Sam Okafor.

Why the WITH?

Window functions run in step 5, with SELECT, after WHERE. So WHERE rank() OVER (…) = 1 is an error: "window functions are not allowed in WHERE". Compute the rank in a CTE, then filter it.

!

Delete NULLS LAST and Mathematics's top earner becomes Noor Haddad, whose salary is unknown: descending order puts NULL first.

Run it, then delete NULLS LAST, playground example 4.3

ORDER BY inside OVER gives running totals

SELECT year, semester,
  count(*) AS enrolled,
  sum(count(*)) OVER
    (ORDER BY year, semester)
    AS running
FROM takes
GROUP BY year, semester;

With ORDER BY, the window for each row is every row up to and including it. The aggregate count(*) runs first, per group; the window sum(…) then runs over the grouped rows.

Run it and see the chart, playground example 4.4

What to take away

  1. 1
    Aggregates skip NULLs; count(*) does not.

    Over no rows, count is 0 and the others are NULL.

  2. 2
    Every SELECT column is grouped or aggregated.

    WHERE filters rows before grouping; HAVING filters groups after.

  3. 3
    After a LEFT JOIN, count a right-hand column.

    count(*) counts the padded row.

  4. 4
    Prefer NOT EXISTS for "has none" and "every".

    It is never unknown; NOT IN and ALL can be.

  5. 5
    Name steps with WITH; rank with window functions.

    Windows keep every row; filter their result in an outer query.
