Part B: ten questions in SQL

Try each statement in the playground's scratch pad first, inside BEGIN; … ROLLBACK;, then copy it into lab4.sql under its comment. Every question ends with a SELECT: write the number of rows it returned in lab4_answers.txt.   1. Q1. Create a table classroom with a building (up to 15 characters), a room_number (up to 7 characters) and a capacity that must be given and must be more than 0. A room is identified by its building and room number together. Insert four rooms: Hale 101 for 120, Hale 214 for 40, Kirk 110 for 60 and Linden 7 for 25. Then show the whole table, sorted by building and room number. Keep the DROP TABLE IF EXISTS classroom; line above it.

  2. Q2. Add an integer column level to course. Fill it, with one UPDATE, with the hundreds of the course number: CS-101 is level 100, CS-347 is level 300. Then show course_id and level, highest level first, then by course. Hint: substring(course_id FROM '[0-9]+') gives the digits as text, and integer division by 100 drops the rest.

  3. Q3. Ines Duarte, id 91011, joins Comp. Sci. at 88,000 and will teach CS-319 in Fall 2027. Insert both rows. Then show every course's course_id with the number of times it has been taught as times_taught, 0 included, sorted by course.

  4. Q4. In one UPDATE, give every instructor paid under 70,000 a 4% raise and everyone else 2%. Then show every instructor's name and salary, sorted by name.

  5. Q5. Delete every enrollment in a course offered by the Music department. Use a subquery: takes has no department column. Then show the number of enrollments left as enrollments.

  6. Q6. Add a constraint named grade_valid to takes that allows only the grades A, A-, B+, B, B-, C+, C, C-, D and F. Then run these two INSERTs exactly as they are, and show the number of enrollments as enrollments. One of the INSERTs is meant to fail; your output file should show its error.

    INSERT INTO takes VALUES ('12345', 'MA-201', 'Spring', 2027, 'E');
INSERT INTO takes VALUES ('12345', 'MA-201', 'Spring', 2027, NULL);

  7. Q7. Create a view transcript with each enrollment's student id, student name, course title, semester, year, grade and credits. Then use the view to show Morgan Lee's title, semester, year and grade, sorted by year, then semester (Spring before Fall), then title.

  8. Q8. Create a view dept_stats with every department's name and its numbers of instructors, students and courses, 0 included. Then show the whole view, sorted by department. Join all four tables in one query; Part C asks what goes wrong if you are not careful.

  9. Q9. Every course a student must pass before CS-319, directly or through other courses: prereq_id, the course title and depth, where depth 1 is a direct prerequisite, 2 a prerequisite of one of those, and so on. If a course can be reached in more than one way, show its smallest depth. Sort by depth, then by course. Use WITH RECURSIVE.

Change the foreign keys takes_id_fkey and advisor_s_id_fkey to ON DELETE CASCADE: drop each and add it again under the same name, in one ALTER TABLE per table. Part C: two short answers

Answer in lab4_answers.txt, two to four sentences each. Run the queries first; the numbers are part of the answer.

  1. W1. Here is dept_stats written the obvious way, for one department. Put it in lab4.sql under the W1 comment, after Q10, and run the file. Give the three counts it shows for Comp. Sci. and the true counts from your Q8. Then explain where the extra rows come from, and why count(DISTINCT …) fixes it.

    SELECT d.dept_name, count(i.id) AS instructors,
       count(s.id) AS students, count(c.course_id) AS courses
FROM department d
LEFT JOIN instructor i ON i.dept_name = d.dept_name
LEFT JOIN student s    ON s.dept_name = d.dept_name
LEFT JOIN course c     ON c.dept_name = d.dept_name
WHERE d.dept_name = 'Comp. Sci.'
GROUP BY d.dept_name;

  2. W2. In Q6, one INSERT failed and the other worked. Which one, and why did grade_valid let the second one in? How would you stop a NULL grade, if you wanted to, and why might the registrar not want to?

If something goes wrong

  • "university.sql: No such file or directory": lab4.sql and university.sql are not in the same folder. Move them together and run again.
  • "relation … already exists": you ran part of the file on its own, outside the reload. Run the whole file; the reload drops everything the lab creates.
  • "violates foreign key constraint" on a DELETE: rows elsewhere still point at the row you are deleting (slide 8). In Q10 that means the constraint was not replaced; check its name with \d takes.
  • "check constraint … is violated by some row" when adding a constraint: a row already breaks the rule. Find it with a SELECT using the opposite condition.
  • A count that is too high in Q8: see W1.
  • "permission denied to create role" in Q12: your PostgreSQL user is not allowed to create roles. Run psql as the postgres user (-U postgres), which can; in Colab you already are.
  • "syntax error at or near "$$"" in Q11: the function body must be closed with END $$; and the dollar signs must match (slide 25).
  • Anything else: copy the exact message and bring it to office hours, Tuesday and Wednesday 12:00–3:00 p.m., MIC room D159, or email it to me.
