Reading one table well

Expressions and aliases in SELECT, patterns and ranges in WHERE, and ORDER BY and LIMIT to shape the result.

  • Strings: || joins two strings. upper(), length() and many more are built in.
  • AS names a column. Without it PostgreSQL invents a name such as ?column?.

ORDER BY sorts; LIMIT keeps the first rows

FROM instructor

LIMIT 3;
Result: 3 rows

  • Without ORDER BY, row order is not promised. It can change between runs.
  • Ties are broken by the next key: name above.
  • NULLs sort as larger than any value in PostgreSQL, so DESC puts Noor Haddad's NULL salary first. NULLS LAST moves it.
  • LIMIT n OFFSET k skips k rows, then keeps n. The standard spelling is FETCH FIRST n ROWS ONLY.

Joining tables

JOIN … ON is the algebra's theta join. Every way of writing it gives the same rows; the clearest one is the one to use.

An inner join keeps the pairs that match

SELECT i.name, t.course_id
FROM instructor i JOIN teaches t ON i.id = t.id;

One join, four spellings

-- 1. JOIN ... ON: say exactly what matches
SELECT s.name, c.title
FROM takes t
JOIN course c ON t.course_id = c.course_id
JOIN student s ON s.id = t.id;

-- 2. USING: the columns share a name
SELECT name, title
FROM takes JOIN course USING (course_id)
           JOIN student USING (id);
-- 3. Comma join: the product, then WHERE
SELECT s.name, c.title
FROM takes t, course c, student s
WHERE t.course_id = c.course_id
  AND s.id = t.id;

-- 4. NATURAL JOIN: 14 rows, not 22
SELECT name, title
FROM takes NATURAL JOIN course
           NATURAL JOIN student;
§

Spellings 1 to 3 return the same 22 rows. Spelling 4 also matches dept_name, because course and student both have one, so it keeps only students taking a course in their own department: 14 rows. A NATURAL JOIN is fragile: add a column to a table and your query changes meaning. Prefer ON or USING.

A self join compares rows of the same table

-- instructors who earn more than
-- someone in their own department
SELECT DISTINCT a.name, a.salary
FROM instructor a
JOIN instructor b
  ON a.dept_name = b.dept_name
 AND a.salary > b.salary
ORDER BY a.name;
Result: 4 rows

Table alias

A second name for a table in one query. a and b are two independent walks over instructor: the algebra's ρ, from slide 10 last week.

  • Without aliases the query cannot say which copy it means.
  • DISTINCT matters: Avery Chen earns more than two Comp. Sci. colleagues and would appear twice.
  • a.salary > b.salary also stops a row from matching itself.

Longer questions follow the foreign keys

-- which students took a course
-- from Avery Chen, in the same term?
SELECT DISTINCT s.name, c.title
FROM instructor i
JOIN teaches t  ON t.id = i.id
JOIN takes   k  ON k.course_id = t.course_id
               AND k.semester  = t.semester
               AND k.year      = t.year
JOIN student s  ON s.id = k.id
JOIN course  c  ON c.course_id = t.course_id
WHERE i.name = 'Avery Chen';
  1. 1
    Start from what you know.

    The instructor's name.

  2. 2
    Walk one foreign key per JOIN.

    instructor → teaches → takes → student.

  3. 3
    Match every part of the key.

    A section is course, semester and year together.

Result: 10 rows, from CS-101 and CS-347 in Fall 2025 and CS-315 in Spring 2026.

Outer joins

An inner join silently drops every row without a partner. An outer join keeps them, and fills the missing side with NULL.

LEFT JOIN keeps every row of the left table

SELECT i.name, t.course_id
FROM instructor i LEFT JOIN teaches t ON i.id = t.id;   -- 15 rows on the full tables

LEFT, RIGHT and FULL choose which unmatched rows to keep

Find what is missing: LEFT JOIN … IS NULL

-- courses nobody teaches
SELECT c.course_id, c.title
FROM course c
LEFT JOIN teaches t
       ON t.course_id = c.course_id
WHERE t.course_id IS NULL;
Result: 1 row

Anti-join

The rows of one table that have no partner in another. In the algebra: course − (course ⋉ teaches).

  • The left join pads each course with no section with NULL.
  • WHERE t.course_id IS NULL keeps exactly those padded rows.
  • Test a column that cannot be NULL in a real match: here the join column itself.

Week 4 writes the same question with NOT EXISTS.

In an outer join, ON and WHERE are not the same

Rule of thumb: conditions on the right table of a LEFT JOIN go in ON; conditions on the left table go in WHERE. In an inner join the two places give the same answer.

NULLs in practice

Last week: a comparison with NULL is unknown, and WHERE keeps only true rows. This week: where that rule surprises people.

COALESCE(a, b, …)

Returns the first argument that is not NULL. The usual way to show a default in a report.

SELECT i.name,
       COALESCE(t.course_id, '(none)') AS teaches
FROM instructor i
LEFT JOIN teaches t ON t.id = i.id;

NULLIF(a, b) does the reverse: NULL when a = b, else a. IS DISTINCT FROM is a comparison that treats two NULLs as equal and never returns unknown.

NOT IN and a single NULL

SELECT dept_name FROM department
WHERE dept_name NOT IN
  (SELECT dept_name FROM student);  -- 0 rows
SELECT dept_name FROM department
WHERE dept_name NOT IN
  (SELECT dept_name FROM student
   WHERE dept_name IS NOT NULL);    -- Economics

Set operations

UNION, INTERSECT and EXCEPT combine whole query results, row against row.

UNION, INTERSECT and EXCEPT, with and without ALL

SELECT course_id FROM teaches WHERE semester = 'Fall'   AND year = 2025
UNION
SELECT course_id FROM teaches WHERE semester = 'Spring' AND year = 2026;

The rules for combining queries

  1. 1
    Same number of columns, compatible types.

    Matched by position, not by name.

  2. 2
    The first query names the columns.

    Aliases in later queries are ignored.

  3. 3
    One ORDER BY, at the very end.

    It sorts the combined result.

  4. 4
    Set operations treat NULLs as equal.

    Unlike =, two NULLs are duplicates here.

-- everyone in Physics, labelled
SELECT name, 'instructor' AS role
FROM instructor WHERE dept_name = 'Physics'
UNION ALL
SELECT name, 'student'
FROM student WHERE dept_name = 'Physics'
ORDER BY role, name;

Result: 6 rows, 2 instructors then 4 students. INTERSECT binds tighter than UNION and EXCEPT; use parentheses when you mix them.

What to take away

  1. 1
    FROM, WHERE, SELECT, ORDER BY, LIMIT: that is the run order.

    It explains which aliases work where.

  2. 2
    Join with ON or USING; avoid NATURAL JOIN.

    Match every column of a composite key.

  3. 3
    Outer joins keep the unmatched rows, padded with NULL.

    LEFT JOIN … WHERE key IS NULL finds what is missing.

  4. 4
    A filter on the right table of a LEFT JOIN goes in ON.

    In WHERE it turns the outer join into an inner one.

  5. 5
    NULL makes comparisons unknown.

    Use IS NULL, COALESCE, and be wary of NOT IN.
