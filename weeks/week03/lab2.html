Part B: ten questions in SQL

Try each query in the playground's scratch pad, then copy it into lab2.sql under its comment. Write the number of rows it returned in lab2_answers.txt. Show exactly the columns asked for, in the order asked.

  1. Q1. The course_id, title and credits of every 4-credit course, sorted by title.

  2. Q2. The name and total credits of every student with between 50 and 100 credits, both included, most credits first.

  3. Q3. For every instructor in Physics or Biology: name, salary, and the salary after a 4% raise, rounded to cents and named raised. Use IN.

  4. Q4. Every grade given in Fall 2025: the student's name, the course title and the grade, sorted by student name and then title.

  5. Q5. The name of every student whose advisor earns more than 90,000, with the advisor's name.

  6. Q6. Every department with the names of its instructors, sorted by department and then name. A department with no instructors must still appear once.

  7. Q7. The names of students who have never taken a course. Use an outer join.

  8. Q8. The names of instructors who both teach at least one course and advise at least one student. Use INTERSECT on ids, then get the names.

  9. Q9. Every enrollment that did not earn an A: the student's name, the course_id, and the grade. A course with no grade yet counts as "not an A", and its grade must show as the text in progress.

  10. Q10. The names of students who took a section taught by their own advisor, each name once. A section is one course in one semester of one year.

§

Check yourself: Q1 returns 4 rows, Q6 returns 12 and Q7 returns 1. If Q9 returns 14 rows, the three courses with no grade yet have gone missing; slide 21 says why. If Q10 returns more than 7, your join is matching the course but not the semester and year.

When every query works, run the whole file in your own PostgreSQL:

psql -d university -e -f lab2.sql > lab2_output.txt 2>&1

The -e prints each query above its result, so the grader can match them.

Part C: two short answers

Answer in lab2_answers.txt, two to four sentences each. Run the queries first; the counts are part of the answer.

  1. W1. This query is meant to list every student who is not in a department housed in Hale. It returns 7 rows, but Emery Walsh is missing, and Emery Walsh is not in a Hale department either. Explain why, using what NOT IN does when it meets a NULL.

    SELECT name FROM student
WHERE dept_name NOT IN (SELECT dept_name FROM department WHERE building = 'Hale');

  2. W2. Run both queries and give each count. Explain in your own words why moving t.year = 2027 from ON to WHERE changes the answer.

    SELECT s.name, t.course_id
FROM student s LEFT JOIN takes t ON t.id = s.id AND t.year = 2027;

SELECT s.name, t.course_id
FROM student s LEFT JOIN takes t ON t.id = s.id
WHERE t.year = 2027;

If something goes wrong

  • "relation "teaches" does not exist": your database is still the week 1 version. Reload university.sql from this page.
  • "column reference "id" is ambiguous": two joined tables both have id. Give each table an alias and write s.id or t.id.
  • "column … does not exist" for a name you made with AS: WHERE runs before SELECT (slide 4), so repeat the expression in WHERE.
  • More rows than you expect: a join condition is missing, or a student matches several rows. Check every join has an ON that uses the key, and add DISTINCT where the question says "each once".
  • A row you need has disappeared after a LEFT JOIN: a WHERE condition on the right-hand table removed the padded rows (slide 18).
  • Anything else: copy the exact message and bring it to office hours, Tuesday and Wednesday 12:00–3:00 p.m., MIC room D159, or post it in the week 3 discussion in Brightspace.
