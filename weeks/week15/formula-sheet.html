Final Exam: the formula sheet

This exact page is the last page of the final exam, and it is inside the online quiz. You bring nothing else: no notes, no calculator. Learn what is here so you don't have to read it for the first time in the exam.

Relational algebra

  • σp(r): the rows of r where p holds · πA(r): the columns A of r, duplicates removed · ρx(r): r renamed x
  • r × s: every pair of rows · r ⋈ s: pairs that agree on the common attributes, which appear once · r ⋈θ s = σθ(r × s)
  • r ∪ s, r ∩ s, r − s: r and s must have the same attributes
  • r ÷ s, where s's attributes S are among r's: the rows t of πR−S(r) such that t combined with every row of s is in r
  • Conditions use =, ≠, <, ≤, >, ≥ and ∧ (and), ∨ (or), ¬ (not)

SQL

  • A query is evaluated in this order: FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY
  • A comparison with NULL is unknown; WHERE and HAVING keep only rows where the condition is true. count(*) counts rows; count(col) and the other aggregates skip NULL

Functional dependencies and normal forms

  • Armstrong's axioms. Reflexivity: if β ⊆ α, then α → β. Augmentation: if α → β, then γα → γβ. Transitivity: if α → β and β → γ, then α → γ
  • Closure α+: start with α; while some β → γ in F has β ⊆ α+, add γ. α is a superkey of R if α+ = R; a candidate key is a minimal superkey; an attribute is prime if it is in some candidate key
  • BCNF: for every nontrivial α → β that holds, α is a superkey
  • 3NF: for every nontrivial α → β that holds, α is a superkey, or every attribute of β − α is prime
  • A decomposition of R into R1, R2 is lossless if R1 ∩ R2 → R1 or R1 ∩ R2 → R2. It preserves dependencies if the dependencies that hold on each Ri together imply all of F

Indexes

  • A B+-tree with fanout f (entries per page) over n keys has about ⌈logf n⌉ levels. Finding one row by key reads one page per level, plus the row's page in the table

Join costs, in pages read (r is the outer input)

  • br, bs: pages of r and s · nr, ns: rows of r and s
  • Block nested loop: br × bs + br
  • Indexed nested loop: br + nr × c, where c is the cost of one lookup in the index on s
  • Merge join, inputs already sorted: br + bs · Hash join, hash table on one input fits in memory: br + bs

Estimates

  • Rows kept = selectivity × nr. V(A, r): number of distinct values of A in r
  • A = v: 1 / V(A, r), assuming every value is equally common; for a value in the common-values list, its listed frequency
  • A < v: (v − min) / (max − min) · p1 ∧ p2: the product of the two selectivities, assuming independence
  • r ⋈ s on A: at most nr rows if A is a key of s and a foreign key in r; otherwise nr × ns / max(V(A, r), V(A, s))
  • σθ(r ⋈ s) = σθ(r) ⋈ s when θ uses only attributes of r

Transactions and recovery

  • Two operations conflict if they belong to different transactions, use the same item, and at least one is a write. Precedence graph: an edge Ti → Tj for each conflicting pair where Ti's operation comes first; a schedule is conflict serializable if the graph has no cycle
  • Log records: <T start>, <T, X, old value, new value>, <T commit>, <T abort>, <checkpoint L> with L the active transactions. Undo writes the redo-only record <T, X, old value>

Replication

  • N copies, writes wait for W, reads ask R: every read sees the latest write if R + W > N
